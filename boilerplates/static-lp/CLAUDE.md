# static-lp

このテンプレートから scaffold したプロジェクトで作業する AI アシスタント向けの方針。

## このリポジトリの性格

**表示専用の静的サイト**である。分岐もサーバー状態も持たない静的 HTML を、ビルド時
プリレンダリング（SSG）で生成して配信する。この前提を外して設計しないこと（DB・
セッション・API サーバーは想定しない。動的な機能が必要になった場合は
`react-spa-cloudflare` テンプレート相当の構成への切り替えを検討する）。

## 🔴 静的コンテンツにテストを作り込まない

グローバルの 80% カバレッジ要件をこのテンプレートに機械的に適用しないこと
（`rules/testing.md` の「静的コンテンツにテストを作り込まない」節に準拠。
`vitest.config.ts` の `coverage.include` は既にこの方針に沿って設定済み）。

### やってはいけないこと

- ❌ **ページ・セクションごとの描画テストを書く** — コンポーネントが読むのと同じ
  原稿（文言・content モジュール）を test 側でも import して突き合わせるのは
  同語反復。原稿が間違っていても通る
- ❌ **カバレッジを上げるためにファイルを消す / 意味のないテストを足す** — ゲートに
  設計を歪めさせない
- ❌ **カバレッジ対象を `src/**` 全体に戻す** — 表示専用のページ・コンポーネントは
  対象外にしてある（`vitest.config.ts`）

### 代わりにやること

| 守りたいもの | 手段 |
|---|---|
| 分岐のあるコード（リンク判定・設定値・ユーティリティ） | vitest + カバレッジゲート（対象は `src/config/**` `src/lib/**` `src/hooks/**`） |
| ページの欠落・リンク切れ | `src/App.test.tsx` の統合テスト（`describe("App link integrity")`。`App` 全体を render して検証） |
| レイアウト崩れ・コントラスト・はみ出し | Playwright のスクリーンショット（`docs/visual-check.md`） |

`src/App.test.tsx` の `App link integrity` が検証しているのは次の3点。ページや
リンクを追加したときも、ここを増やす基準は「実際に壊れうるか」で判断する。

1. ページ内アンカー（`#foo`）が同一ページ上の `id="foo"` として実在する
2. 内部リンク（`/foo`）が `src/routes.ts` の `KNOWN_PATHS` に対応する
3. 空 / `#` のみ / `undefined` な href が存在しない

**この方針は「失敗しているテストを消す」ことの許可ではない。** 落ちているテストを
消すのは禁止（グローバル `rules.md` の Never Skip Tests）。検知できない対象に
検証手段を割り当てない、という設計判断である。

## 原稿・コンテンツの扱い

本テンプレートは原稿を集約する `src/content/` を持たない（`HomePage.tsx` 等に
プレースホルダの文言を直接書いている）。実際のセクション数が増える場合は、
原稿をコンポーネントから分離する構成（例: `src/content/*.ts` に文言を集約し、
コンポーネント側では import するだけにする）を検討し、コンポーネント側に長い
文言を直接書き込みすぎないようにする。

## 外部リンクの扱い

- 外部 URL・問い合わせ先メール等は `src/config/links.ts` に集約する（直書き禁止）
- **リンク先が未確定の CTA を押せるボタンとして描画しない**。`LinkEntry` の
  `preparing` 状態にしておき、`resolveHref` が `undefined` を返す間は UI 側で
  非活性表示にする（クリックして何も起きない導線は信頼を損なう）

## SEO・プリレンダリング

- ページを追加・削除したら `src/router.tsx` の Route 定義と `src/routes.ts` の
  `KNOWN_PATHS` の両方を更新すること（単一ソースではなく二箇所に定義が必要。
  `src/routes.ts` のコメント参照）
- `scripts/verify-prerender.mjs` の期待テキスト（見出し文言）はハードコードして
  いるため、ページの見出しを変更したらあわせて更新すること
- `public/sitemap.xml` は自動生成していない。`KNOWN_PATHS` の変更に合わせて
  手動で同期すること

## デプロイ

- 手順は `docs/deploy.md`（Cloudflare Pages, Direct Upload 方式）
- `CLOUDFLARE_API_TOKEN` 等の認証情報の実値をコード・ログ・issue・PR・コミット
  メッセージに書かない（`rules/security.md` の外部システムへの投稿前チェックに従う）

## やらないこと（デフォルトのスコープ外）

会員機能 / CMS・ブログ基盤 / 自前決済 / 問い合わせ内容の DB 保存 / 動的な
データ取得（API 連携）。これらが必要な場合は静的サイトの前提が崩れるため、
`react-spa-cloudflare` 等の動的な構成への切り替えを検討すること。
